## 2. 公司业务边界

公司的首要业务是交付软件项目，例如开发一个小程序。大秘书负责人与公司的交互，项目经理负责软件工程管理，研发岗位池提供现有 Pi Agent 已具备的规划、架构、开发、测试、安全分析和复核能力。

其他岗位只服务于公司正常运行：

| 业务类型 | 主责岗位 | 直接结果 |
|---|---|---|
| 请求受理与派发 | `administration.chief-secretary` | 请求被正确交接，或能力缺口被提交 CEO |
| 软件项目交付 | `operations.project-manager` | 经过测试、独立复核和项目经理验收的软件成果 |
| Token 记账与查询 | `finance.token-accountant` | 可追溯的 Token 汇总和口径说明 |
| 公司运行维护 | `operations-support.specialist` | 已验证并恢复运行的修复，或明确的失败结果 |
| Agent 配置维护 | `human-resources.agent-trainer` | 通过检查并在授权范围内应用的 Agent 配置 |

不属于软件开发或上述支持范围的任务，不交给项目经理或大秘书兜底执行。大秘书必须说明当前没有合适岗位，并请 CEO 决定是否由 Agent 培训专员设计新岗位或 Agent。

## 3. 业务类型

### 3.1 `administration.chief-secretary/request-intake-and-routing`

#### 目标与边界

| 属性 | 内容 |
|---|---|
| 业务目标 | 在 Pi 会话中接收 CEO 请求，澄清必要信息并交给合适岗位 |
| 主责岗位 | `administration.chief-secretary` |
| 输入 | CEO 的指令、查询、项目或确认；专业岗位的结果和待决事项 |
| 必要产出 | 已确认接收的专业任务、当前会话回复，或能力缺口说明 |
| 完成条件 | 短请求已回复；长任务已进入后台并被责任岗位接收；能力缺口已提交 CEO |
| 非目标 | 代替专业岗位执行开发、财务、运维或 Agent 配置工作 |

#### 典型业务

1. 大秘书在当前 Pi 会话中理解请求并补充完成派发所需的上下文。
2. 可在当前会话内完成的查询交给专业岗位，取得结果后直接回复 CEO。
3. 需要长期执行的软件项目交给项目经理进入后台，当前 Pi 会话可以结束。
4. 后台顶层任务完成、最终失败或等待 CEO 决策时，大秘书按 M3 邮件规则通知 CEO。
5. 没有匹配岗位时，大秘书说明能力缺口，不自行执行，也不把任务强行交给项目经理。

#### 能力需求

- 读取组织、岗位、顶层任务状态和专业岗位返回的结果摘要。
- 创建和派发顶层任务，接收完成回调和待决事项。
- 在当前 Pi 会话回复 CEO。
- 将允许的异步事件加入 CEO 邮件队列并处理确认。
- 保留原始意图，避免把自然语言转交变成权限扩张。

### 3.2 `operations.project-manager/software-project-delivery`

#### 目标与边界

| 属性 | 内容 |
|---|---|
| 业务目标 | 将 CEO 的软件需求转化为经过测试、独立复核和技术验收的项目成果 |
| 主责岗位 | `operations.project-manager` |
| 输入 | 大秘书派发的软件任务、CEO 原始要求、项目工作区和相关上下文 |
| 必要产出 | 软件成果、验证证据、必要技术文档、完成报告或明确失败结果 |
| 完成条件 | 项目经理完成技术验收并把顶层结果交回大秘书 |
| 非目标 | 数学研究等非软件任务；要求 CEO 审批每份内部 Plan；重新实现 Pi subagent 执行器 |

#### 典型业务

1. 项目经理确认目标、范围、约束和可观察的验收条件。
2. 必要时先调用只读 Subagent 勘察代码或验证技术可行性。
3. 项目经理自主形成内部 Plan，覆盖目标、范围、架构、任务、测试、验收和主要风险。
4. 项目经理使用现有 Pi `subagent` 能力选择单任务、并行或链式委派，由研发 Agent 完成实现和验证。
5. 所有代码成果必须运行适用测试，并由未参与编写的另一个调用实例独立复核。
6. 项目经理根据完整成果和证据决定验收、继续修改或最终失败。
7. 顶层结果交给大秘书；研发子任务的普通成功和失败不直接通知 CEO。

#### 能力需求

- 在获派项目工作区内读取、修改文件、运行常规开发命令，并进行本地 Git 分支和提交。
- 读取 CEO 要求和项目上下文，创建内部 Plan、父子任务和 Artifact 引用。
- 发现并调用具备 `developer`、`tester`、`security-engineer` 和 `reviewer` 能力的研发 Agent。
- 接收 Harness 的流式状态、最终结果、失败、中止和 Token usage。
- 对所有代码项目执行测试和独立复核；根据风险决定是否增加专项安全检查。
- 对越界、不可逆、外部发布、付款、凭证或扩大范围的操作请求 CEO 授权。

### 3.3 `finance.token-accountant/token-accounting-and-query`

#### 目标与边界

| 属性 | 内容 |
|---|---|
| 业务目标 | 自动保存模型 Token 消耗，并按 CEO 请求提供准确的统计结果 |
| 主责岗位 | 运行系统负责记账；`finance.token-accountant` 负责查询和说明 |
| 输入 | 模型 usage、Agent、Provider、Model 及可用的部门、项目和任务归属 |
| 必要产出 | `CostRecord` 账本；回答 CEO 问题的 Token 汇总和数据缺口说明 |
| 完成条件 | usage 已追加到账本，或财务已把查询结果交回大秘书 |
| 非目标 | 修改或补录成本记录；货币会计；软预算或硬预算控制 |

#### 典型业务

1. 运行系统在每次取得最终模型 usage 后恰好追加一条 `CostRecord`。
2. CEO 在 Pi 会话中提出 Token 查询，大秘书把问题交给财务。
3. 财务通过只读 SQLite 连接，自由执行只读 SQL 查询成本账本和归属视图。
4. 财务按问题选择 Agent、部门、项目、Provider、Model 或时间维度进行汇总。
5. 财务说明统计范围和缺失数据，将结果交回大秘书在当前会话回复。

#### 能力需求

- 自动、幂等地记录模型 usage，原始账本只追加。
- 为财务提供只读 SQLite 连接，但只暴露成本账本和必要的 Agent、部门、项目归属视图。
- 财务可以编写只读 SQL、汇总数据和解释统计口径，不能读取业务消息、Prompt、凭证或项目源码。
- usage 缺失、重复或无法归属时必须明确记录，不能捏造或静默丢弃。

### 3.4 `operations-support.specialist/runtime-maintenance`

#### 目标与边界

| 属性 | 内容 |
|---|---|
| 业务目标 | 发现、诊断并修复公司 Agent 系统故障，安全恢复运行 |
| 主责岗位 | `operations-support.specialist`；独立 Supervisor 负责实际重启和回滚 |
| 输入 | 健康状态、计划内单元测试、日志、运行版本和故障上下文 |
| 必要产出 | 通过测试和独立复核的候选修复，以及 Supervisor 的恢复或回滚结果 |
| 完成条件 | 公司系统恢复健康，或修复失败并形成可追溯的顶层事故结果 |
| 非目标 | 承接普通软件项目；由 Agent 直接重启自身所在进程；跳过验证应用修复 |

#### 典型业务

1. 运行系统或 Supervisor 执行健康检查和计划内单元测试。
2. 运营保障读取日志、代码和配置，自行诊断并形成最小修复。
3. 专员运行规定测试，并调用一个未参与修复的只读 reviewer。
4. 测试和复核均通过后，专员把候选修复提交给运行时之外的 Supervisor。
5. Supervisor 应用候选版本、重启、检查健康；失败时恢复上一个已知可用版本。
6. fatal 异常在确认时进入大秘书邮件队列，恢复或失败结果更新相应事故信息。

#### 能力需求

- 读取公司 Agent 系统的健康状态、日志、测试、源码、配置和版本信息。
- 在限定的公司系统工作区内修改代码和配置、运行测试并调用只读 reviewer。
- 通过受控接口请求 Supervisor 应用候选修复，Agent 本身不能直接控制宿主进程。
- Supervisor 独立于公司运行时，能够检测退出、启动已知版本、健康检查和回滚。
- 重启造成的模型调用标记为中断，由原责任岗位决定后续处理，不自动从头执行。

### 3.5 `human-resources.agent-trainer/agent-configuration-management`

#### 目标与边界

| 属性 | 内容 |
|---|---|
| 业务目标 | 根据公司需要设计岗位和维护 Agent Prompt、Skill、`AGENTS.md` 与 Agent 定义 |
| 主责岗位 | `human-resources.agent-trainer` |
| 输入 | CEO 或大秘书提出的岗位、能力或 Agent 配置需求 |
| 必要产出 | 通过格式、引用、权限边界和必要行为检查的配置变更 |
| 完成条件 | 常规变更已应用并汇报；受控变更已取得 CEO 决定或停止 |
| 非目标 | 通用人事管理；自行创建业务需求；通过 Prompt 扩大系统权限 |

#### 典型业务

1. 培训专员读取现有组织、岗位职责、Agent 定义和相关配置。
2. 专员根据明确需求编写或修改 Prompt、Skill、`AGENTS.md`、Agent 定义或岗位方案。
3. 专员检查格式、引用、职责一致性和必要的行为验证。
4. 既有职责和权限内的常规变更通过检查后直接应用。
5. 扩大 Tool 或数据权限、修改组织、接入凭证的变更必须提交 CEO 批准。
6. 结果交回大秘书；配置内容不得保存明文密钥。

#### 能力需求

- 读取组织、业务目录、岗位定义和 Agent 配置工作区。
- 创建和修改 Prompt、Skill、Agent 定义以及项目或产品级 `AGENTS.md`。
- 运行结构校验和受限的 Agent 行为检查，保留版本与变更说明。
- 区分能力指导与权限配置，确保 Prompt 不能绕过运行系统授权。

## 4. M4 能力输入

M4 应依据以上五类业务实现最小运行闭环，而不是按旧目录逐项实现 Tool。必要的逻辑边界为：

| 能力 | 首版用途 |
|---|---|
| 顶层任务与父子任务 | 连接 CEO 请求、项目经理委派和最终结果 |
| 内部消息与完成回调 | 支持大秘书派发、专业岗位接收和后台结果返回 |
| Artifact 引用 | 保存 Plan、代码成果、测试证据、技术文档和报告位置 |
| CostRecord 账本与归属视图 | 自动记账并支持财务只读 SQL |
| 审批与审计 | 保存高危动作授权、拒绝和关键状态变化 |
| 受限邮件队列 | 聚合后台顶层结果、待决事项和 fatal 异常 |
| Subagent 适配 | 复用现有 Pi 执行、状态、usage 和中止能力 |
| 独立 Supervisor | 启动、重启、健康检查和失败回滚 |

具体规则、权限和通知门禁以 `RUNTIME_DESIGN.md` 为准。
